## 一、工程总览

真正要读的代码在：

```text
robomaster-inschool/RM2027_School_Comp_Frame/
```

仓库根目录里的 `RM2027校内赛机械资料V1.0` 是 SolidWorks 机械模型，PDF 和 `.7z` 是规则、环境配置和培训资料，不是代码。根目录另一个 `RM2027_School_Comp_Frame` 里只有一份 README，也不是代码副本。

硬件平台是 **STM32F407IGHx**，也就是 RoboMaster 开发板 C 型。

代码大致分三层：

```text
CubeMX 生成层（Src/、Inc/）
    负责 GPIO、定时器、CAN、串口、ADC、SPI、I2C、USB 等外设初始化

设备驱动层（userCode/devices/）
    Device        板级支持：main、LED、蜂鸣器、ADC 电压、Flash、1ms 中断
    Motor         M3508/M2006 + C620/C610 电调，CAN 通信 + PID
    Servo         舵机 PWM 驱动
    RemoteControl DBUS 遥控器接收机解析

任务逻辑层（userCode/tasks/）
    ChassisTask   麦轮底盘运动解算
    ControlTask   遥控器档位/摇杆映射
    UserTask      学生自己加机构的地方
```

## 二、程序启动与运行主线

### 2.1 启动流程

```text
上电
→ startup_stm32f407xx.s 的 Reset_Handler
→ SystemInit()                 // system_stm32f4xx.c
→ main()                       // 注意：在 userCode/devices/Src/Device.cpp
   → HAL_Init()
   → SystemClock_Config()      // Src/main.c，配到 168MHz
   → MX_GPIO_Init()
   → MX_DMA_Init()
   → MX_TIM5_Init / MX_TIM1_Init / MX_TIM4_Init / MX_TIM10_Init / MX_TIM8_Init
   → MX_ADC1_Init / MX_ADC3_Init
   → MX_USART1_UART_Init / MX_USART6_UART_Init / MX_USART3_UART_Init
   → MX_CAN1_Init / MX_CAN2_Init
   → MX_I2C3_Init / MX_SPI1_Init / MX_SPI2_Init
   → MX_USB_DEVICE_Init()
   → HAL_TIM_Base_Start_IT(&htim5)
   → HAL_TIM_PWM_Start(&htim5, ...)  // RGB LED
   → RemoteControl::init()           // 遥控器 DMA + 空闲中断
   → bsp_flash_read(&flashData)      // 读 Flash 参数
   → HAL_TIM_Base_Start_IT(&htim10)  // 开启 1ms 控制节拍
   → Motor::Init()                   // 启动 CAN
   → ChassisStart()
   → UserInit()
   → init_Flag = 1
→ while(1) { }                 // 主循环是空的
```

**最关键的一句话：这个工程不是靠 `while(1)` 跑控制，而是靠 TIM10 的 1ms 中断跑控制。**

### 2.2 1ms 控制中断

TIM10 配置为 1kHz 更新中断，回调在 `Device.cpp`：

```cpp
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (init_Flag == 0)
        return;

    if (htim == &htim10) {
        aRGB_led_change(period);   // RGB 灯
        bsp_ADC_vccMoni();         // 电池电压

        CtrlHandle();              // 读遥控器，决定底盘/机构动作
        ChassisHandle();           // 麦轮解算 + 四个底盘电机 PID
        UserHandle();              // 学生自定义机构
        Motor::CANPackageSend();   // 把电流值通过 CAN 发给电调

        // 每 21ms 尝试喂一次看门狗
        // ...
    }
}
```

执行顺序可以理解成：

```text
遥控器输入
   ↓
CtrlHandle()          决定“底盘怎么走 / 机构怎么动”
   ↓
ChassisHandle()       把底盘速度分解到四个轮子
   ↓
UserHandle()          控制额外机构
   ↓
Motor::CANPackageSend()  把 PID 算出的电流发给电调
```

### 2.3 其他中断

```text
CAN1/CAN2 接收中断 → Motor::IT_Handle()          // 电调反馈 0x201~0x208
USART3 空闲中断     → RemoteControl::ITHandle()  // 遥控器 DBUS 数据
EXTI0 按键中断      → HAL_GPIO_EXTI_Callback()   // 板载 KEY
SysTick            → HAL_IncTick()
TIM1_UP_TIM10      → HAL_TIM_IRQHandler(&htim1) + HAL_TIM_IRQHandler(&htim10)
```

### 2.4 急停逻辑

```text
遥控器 SC 开关拨到最下面
→ CtrlHandle() 判断 sRight == DOWN_POS
→ ChassisStop() + UserStop()
→ 底盘电机和用户电机全部停转
```

急停是比赛检录必须保证的功能，调试时如果机器人异常运动，第一时间把 SC 拨到最下面。

## 三、用户代码详解

## 3.1 Device.h / Device.cpp

### Device.h

这是板级公共头文件，作用是把所有外设头文件、C 标准库、数学库集中 include 进来，并定义一些公共结构。

主要内容：

- `INRANGE(NUM, MIN, MAX)`：把变量限制在 `[MIN, MAX]` 范围内，PID 里大量使用。
- `flash_data_t`：存 Flash 的数据结构，包含 `robot_ID`、`yaw_zero`、`pitch_zero`、`pat[125]`。
- `ist8310_t`：磁力计数据结构，目前没怎么用。
- `DEVICE_TYPE_E`：设备类型枚举，`MOTOR` / `SERVO`。
- `class Device`：所有设备的抽象基类，里面有两个纯虚函数：
  - `virtual void Handle() = 0;`
  - `virtual void ErrorHandle() = 0;`
- 声明了 `ChassisStart()`、`ChassisHandle()`、`CtrlHandle()`，因为 `Device.cpp` 里的 `main()` 和定时器回调要调用它们。

`Motor` 和 `Servo` 都继承 `Device` 并实现了 `Handle()` / `ErrorHandle()`。`RemoteControl` 也继承 `Device`，但它只当静态工具类用，不实例化，所以没有实现这两个纯虚函数也没关系。

### Device.cpp

这个文件非常重要，**真正的 `main()` 就在这里**，不在 `Src/main.c`。

它包含以下功能。

#### 1. RGB LED

```cpp
void aRGB_led_show(uint32_t aRGB);
void aRGB_led_change(uint32_t period);
```

- `aRGB_led_show()`：把 ARGB 颜色值拆成红绿蓝，写 TIM5 的三个比较寄存器。
  - `TIM5_CH1` → 蓝
  - `TIM5_CH2` → 绿
  - `TIM5_CH3` → 红
  - 对应引脚 `PH10/PH11/PH12`
- `aRGB_led_change()`：做跑马灯颜色渐变，按 `period` 周期循环。
- 板载 `KEY` 按下时会在 `5000ms` 和 `500ms` 两种周期之间切换。

#### 2. 蜂鸣器

```cpp
float bsp_BuzzerOn(float _freq, float _targetVolPct);
void bsp_BuzzerOff();
```

- 使用 `TIM4_CH3`，引脚 `PD14`。
- 根据目标频率计算 `ARR`，再根据音量百分比计算 `CCR`。
- 第一次调用时启动 TIM4 的 PWM，之后只改频率和占空比。

#### 3. 电池电压检测

```cpp
void bsp_ADC_vccMoni();
```

- 先用 `ADC1` 的 `VREFINT` 通道做基准校准，平均 200 次。
- 再用 `ADC3` 的 `IN8`（`PF10`）采集电池分压。
- 计算公式：
  - `vccMoni = ADC值 * 1.25 / VREFINT平均值`
  - `vccBat = vccMoni / 22 * 222`
- 结果放在全局变量 `vccBat` 里。

#### 4. Flash 读写

```cpp
void bsp_flash_write(flash_data_t *_flashData);
void bsp_flash_read(flash_data_t *_flashData);
```

- 使用 STM32F407 的 **Flash Sector 9**，起始地址 `0x080A0000`。
- 用来保存机器人 ID、云台零位等掉电不丢的数据。
- 注意：这两函数目前有一些指针/长度问题，后面“常见坑”里会讲。

#### 5. 按键外部中断

```cpp
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin);
```

- 处理 `KEY`（`PA0`）的上升沿/下降沿。
- 带 50ms 软件消抖。
- 按下/松开切换 LED 跑马灯周期。

#### 6. `main()`

初始化顺序就是前面“程序启动流程”里写的那一套。

几个注意点：

- `MX_IWDG_Init()` 被注释掉了，所以独立看门狗实际上没有启动。
- `HAL_TIM_Base_Start_IT(&htim5)` 开了 TIM5 的更新中断，但 TIM5 的 NVIC 没开，所以不会真正进中断；LED 的刷新实际由 TIM10 里的 `aRGB_led_change()` 完成。
- `init_Flag = 1` 放在所有初始化之后，保证 1ms 中断不会提前跑业务逻辑。

## 3.2 Motor.h / Motor.cpp

这是电机驱动，支持 RoboMaster 的 **M3508 / M2006 + C620 / C610 电调**。

### 3.2.1 头文件里的数据结构

```cpp
typedef struct {
    int16_t angle;    // 转子机械角度，0~8191
    int16_t speed;    // 转子转速，RPM
    int16_t moment;   // 转矩电流
    int16_t temp;     // 温度
} C6x0Rx_t;
```

这是电调通过 CAN 反馈回来的原始数据。

```cpp
typedef struct PID_Regulator_t {
    float ref, fdb;
    float err[4];
    float errSum;
    float kp, ki, kd;
    float componentKp, componentKi, componentKd;
    float componentKpMax, componentKiMax, componentKdMax;
    float output;
    float outputMax;
} PID_Regulator_t;
```

PID 参数结构体，底盘四个电机共用一个。

```cpp
typedef struct {
    PID_Regulator_t* speedPIDp;
    PID_Regulator_t* anglePIDp;
    uint32_t _motorID;
    float reductionRatio;
    MOTOR_CTRL_TYPE_e ctrlType;
} MOTOR_INIT_t;
```

电机初始化结构体。

```cpp
typedef struct {
    float speed;        // 输出轴转速 RPM
    float angle;        // 输出轴角度，度
    float moment;       // 转矩电流
    float temperature;  // 温度
} MOTOR_STATE_t;
```

电机最终状态。

### 3.2.2 电机 ID

```cpp
#define MOTOR_ID_1 0x00000001u
...
#define MOTOR_ID_16 0x00008000u
```

电机 ID 是**位掩码**，不是普通编号。

- `MOTOR_ID_1 ~ MOTOR_ID_8` 对应 CAN1 上的 1~8 号电机。
- `MOTOR_ID_9 ~ MOTOR_ID_16` 对应 CAN2 上的 1~8 号电机。
- `GET_MOTOR_POS(ID)` 用 `log2(ID)` 把位掩码转成 0~15 的位置。

例如：

```text
MOTOR_ID_1 = 0x0001 → log2 = 0
MOTOR_ID_5 = 0x0010 → log2 = 4
MOTOR_ID_9 = 0x0100 → log2 = 8
```

### 3.2.3 `PID::PIDCalc()`

```cpp
float PID::PIDCalc(float target, float feedback)
```

标准的位置式 PID：

```text
误差 = 目标 - 反馈
P = 误差 * kp
I = 误差累计 * ki
D = (本次误差 - 上次误差) * kd
输出 = P + I + D
```

同时做了：

- 积分限幅
- P/I/D 分项限幅
- 总输出限幅

### 3.2.4 `Motor::Init()`

```cpp
void Motor::Init()
```

- 启动 `hcan1` 和 `hcan2`。
- 打开 CAN RX FIFO0 接收中断。
- 配置 CAN 过滤器为“全接收”，所以 0x201~0x208 的反馈都能进来。

### 3.2.5 `Motor::CANPackageSend()`

```cpp
void Motor::CANPackageSend()
```

把 16 个电机的电流值打包成标准 RoboMaster CAN 帧：

| CAN | 电机 ID | 帧 ID |
|---|---|---|
| CAN1 | 1~4 | `0x200` |
| CAN1 | 5~8 | `0x1FF` |
| CAN2 | 9~12 | `0x200` |
| CAN2 | 13~16 | `0x1FF` |

每帧 8 字节，每个电机 2 字节，高字节在前。

### 3.2.6 构造函数

```cpp
Motor::Motor(MOTOR_INIT_t* _init);
Motor::Motor(uint32_t _id, MOTOR_INIT_t* _init);
```

主要做：

- 把当前对象指针登记到 `motorPtrs[can口][位置]`，CAN 接收中断靠它找到对应电机。
- 把电机 ID 或进 `motor_IDs` 位掩码。
- 复制 PID 参数、减速比、控制类型。
- `feedback` 清零，`targetSpeed = 0`。

第二个构造函数是重载，方便“参数相同、ID 不同”的电机共用同一个初始化结构体。

### 3.2.7 `Motor::Handle()`

```cpp
void Motor::Handle()
```

每个电机每 1ms 调用一次：

1. `MotorStateUpdate()` 更新转速、角度、电流、温度。
2. `IntensityCalc()` 用 PID 算出电流指令。
3. 如果 `stopFlag == 1`，把电流强制设为 0；否则写入 `motor_intensity[]`。

### 3.2.8 `Motor::IT_Handle()`

```cpp
void Motor::IT_Handle(CAN_HandleTypeDef *hcan)
```

CAN 接收中断里调用：

- 只处理 `StdId` 在 `0x201~0x208` 的反馈帧。
- 根据 CAN1/CAN2 和 ID 找到对应 `Motor` 对象。
- 解析 8 字节数据：
  - `canBuf[0..1]` → 角度
  - `canBuf[2..3]` → 转速
  - `canBuf[4..5]` → 转矩电流
  - `canBuf[6]` → 温度
- 如果该 ID 没有注册电机，直接返回，避免空指针。

### 3.2.9 `MotorStateUpdate()`

```cpp
void Motor::MotorStateUpdate()
```

- `state.speed = feedback.speed / reductionRatio`：把转子 RPM 换算成输出轴 RPM。
- `state.moment = feedback.moment`
- `state.temperature = feedback.temp`
- 角度做**多圈累计**：
  - 电调反馈角度是 `0~8191`，对应 `0~360°`。
  - 用 `lastRead` 和当前角度判断是否跨过零点。
  - 跨零点时加上或减去 `8192`，再换算成角度。
  - 最后除以减速比，得到输出轴角度。

### 3.2.10 `IntensityCalc()`

```cpp
int16_t Motor::IntensityCalc()
```

支持两种控制方式：

- `SPEED_Single`：单速度环，直接 `PID(targetSpeed, state.speed)`。
- `POSITION_Double`：双环，角度环输出目标速度，再给速度环。

### 3.2.11 对外接口

```cpp
void SetTargetSpeed(float _targetSpeed); // 设目标转速，单位输出轴 RPM
void SetTargetAngle(float _targetAngle); // 设目标角度
void Stop();                             // 停转
```

`SetTargetSpeed()` 和 `SetTargetAngle()` 都会把 `stopFlag` 清 0，所以调用后电机才会真正出力。

## 3.3 Servo.h / Servo.cpp

舵机驱动。

### 3.3.1 头文件

```cpp
typedef enum {
    POSITION_180,   // 180°位置舵机
    SPEED_360       // 360°连续旋转舵机
} SERVO_TYPE_E;
```

```cpp
typedef struct {
    SERVO_TYPE_E servoType;
    uint32_t servoID;
    float firstAngle;
    float angleLimit_Min;
    float angleLimit_Max;
} SERVO_INIT_T;
```

舵机初始化结构体。

ID 也是位掩码：

```cpp
#define SERVO_ID_1 0x001
...
#define SERVO_ID_7 0x040
```

### 3.3.2 舵机通道映射

`Servo.cpp` 里有一张表：

```cpp
const SERVO_HANDLE_T servoInfo[7] = {
    {&htim1, TIM_CHANNEL_1}, // SERVO_ID_1 → PE9
    {&htim1, TIM_CHANNEL_2}, // SERVO_ID_2 → PE11
    {&htim1, TIM_CHANNEL_3}, // SERVO_ID_3 → PE13
    {&htim1, TIM_CHANNEL_4}, // SERVO_ID_4 → PE14
    {&htim8, TIM_CHANNEL_1}, // SERVO_ID_5 → PC6
    {&htim8, TIM_CHANNEL_2}, // SERVO_ID_6 → PI6
    {&htim8, TIM_CHANNEL_3}, // SERVO_ID_7 → PI7
};
```

所以最多接 7 个舵机。

### 3.3.3 舵机 PWM

TIM1 和 TIM8 都是：

- 预分频 `168-1`
- 自动重装 `20000-1`
- 定时器时钟 168MHz / 168 = 1MHz
- 周期 20000 → 20ms → 50Hz

舵机脉宽：

```text
0°   → 0.5ms  → duty = 0.025 → CCR = 500
180° → 2.5ms  → duty = 0.125 → CCR = 2500
```

`AFFINE(0, 180, 0.025, 0.125, angle)` 就是把角度线性映射到占空比。

### 3.3.4 主要函数

```cpp
Servo::Servo(SERVO_INIT_T *servoInit);
```

- 记录 ID、类型、角度限位。
- 根据 `firstAngle` 计算初始占空比，写入 CCR。
- 但注意：构造函数只写 CCR，**没有启动 PWM 通道**。

```cpp
void Servo::SetTargetAngle(float _targetAngle);
```

- 如果 PWM 没启动，先 `HAL_TIM_PWM_Start()`。
- 用 `INRANGE` 把目标角度限制在 `[angleLimit_Min, angleLimit_Max]`。
- 保存 `targetAngle`。

```cpp
void Servo::Handle();
```

- 180° 舵机：每 1ms 根据 `targetAngle` 重新计算占空比并写 CCR。
- 360° 舵机：目前是空的，还没实现速度控制。

```cpp
void Servo::stop();
```

- 停止对应 PWM 通道，舵机断电。

```cpp
void Servo::Init();
```

- 启动 TIM1 和 TIM8 的计数器和中断。
- 但它是 `private`，而且当前工程里没有人调用它。
- 实际舵机是靠 `SetTargetAngle()` 里的 `HAL_TIM_PWM_Start()` 启动的。

## 3.4 RemoteControl.h / RemoteControl.cpp

遥控器接收机驱动，使用 **DBUS/SBUS** 协议。

### 3.4.1 头文件

```cpp
#define SBUS_RX_BUF_NUM 36u
#define RC_FRAME_LENGTH 25u
#define RC_CH_VALUE_OFFSET 1024
```

- 接收缓冲区 36 字节。
- 一帧遥控器数据 25 字节。
- 通道原始值偏移 1024。

```cpp
typedef enum {
    UP_POS = 97u,
    MID_POS = 0u,
    DOWN_POS = 158u
} SWITCH_STATE_E;
```

三位开关的三个档位值。

```cpp
typedef struct {
    float left_col, left_rol;
    float right_col, right_rol;
    SWITCH_STATE_E sLeft;
    uint32_t pat;
    SWITCH_STATE_E sRight;
    int16_t optional[2];
} RC_Info_t;
```

这是最终给任务层用的遥控器信息：

- `left_col`：左摇杆上下，向上 > 0。
- `left_rol`：左摇杆左右，向右 > 0。
- `right_col`：右摇杆上下，向上 > 0。
- `right_rol`：右摇杆左右，向右 > 0。
- `sLeft`：SB 开关（左三档）。
- `sRight`：SC 开关（右三档）。
- `optional[0..1]`：辅助通道。

### 3.4.2 `RemoteControl::init()`

```cpp
void RemoteControl::init()
```

- 使能 USART3 的 DMA 接收。
- 使能 USART3 空闲中断 `IDLE`。
- 配置 DMA1 Stream1：
  - 外设地址 = `USART3->DR`
  - 内存缓冲区 0 = `sbus_rx_buf[0]`
  - 内存缓冲区 1 = `sbus_rx_buf[1]`
  - 长度 36
  - 循环模式
- 使能 DMA。

### 3.4.3 `sbus_to_rc()`

```cpp
void RemoteControl::sbus_to_rc(const volatile uint8_t *sbus_buf)
```

把 25 字节的 DBUS 帧解析成 8 个 11 位通道：

- `ch[0]` ~ `ch[3]`：四个摇杆通道。
- `s[0]`、`s[1]`：两个三位开关。
- `optional[0]`、`optional[1]`：两个辅助通道。

每个通道减 `1024`，再除以 `671`，归一化到大约 `[-1, 1]`。

开关值兼容两种接收机输出：

- `1121 / 1024 / 1182` 这种原始值。
- `97 / 0 / 158` 这种已经减过偏移的值。

代码里用：

```cpp
if (sLeftValue > 512) sLeftValue -= RC_CH_VALUE_OFFSET;
```

做兼容。

### 3.4.4 `ITHandle()`

```cpp
void RemoteControl::ITHandle()
```

USART3 中断里调用：

- 如果是 `RXNE`，清标志。
- 如果是 `IDLE`：
  - 清标志。
  - 根据 DMA 的 `CT` 位判断当前用的是缓冲区 0 还是 1。
  - 关闭 DMA。
  - 计算本次接收长度：`36 - NDTR`。
  - 重置 `NDTR = 36`。
  - 切换缓冲区。
  - 重新使能 DMA。
  - 如果帧长度等于 25，调用 `sbus_to_rc()` 解析。
  - 如果帧的第 23 字节为 0，说明接收机正常，尝试刷新看门狗。

### 3.4.5 `USART3_IRQHandler()`

```cpp
void USART3_IRQHandler(void)
{
    RemoteControl::ITHandle();
}
```

注意：`Src/stm32f4xx_it.c` 里的 `USART3_IRQHandler` 被注释掉了，真正的实现放在这里，避免重复定义。

## 3.5 ChassisTask.h / ChassisTask.cpp

底盘任务，负责四个麦轮电机的解算和控制。

### 3.5.1 头文件里的参数

```cpp
#define WHEEL_DIAMETER 0.1525f   // 麦轮直径，米
#define REDUCTION_RATIO 19.0f    // M3508 减速比
#define TRACK_WIDTH 0.40f        // 轮距，米
#define WHEEL_BASE 0.38f         // 轴距，米
```

```cpp
#define RPM2RADpS(num) (num * (3.1415926f / 30.0f))
#define RADpS2RPM(num) (num / (3.1415926f / 30.0f))
```

RPM 和 rad/s 互转。

### 3.5.2 底盘电机

```cpp
Motor CMFL(MOTOR_ID_1, &chassisMotorInit); // 左前
Motor CMFR(MOTOR_ID_2, &chassisMotorInit); // 右前
Motor CMBL(MOTOR_ID_3, &chassisMotorInit); // 左后
Motor CMBR(MOTOR_ID_4, &chassisMotorInit); // 右后
```

- 四个 M3508，ID 1~4，接 CAN1。
- 减速比 19。
- 速度单环。
- PID 参数：`kp = 60`，`outputMax = 16384`。

### 3.5.3 `ChassisStopFlag`

```cpp
uint8_t ChassisStopFlag = 1;
```

默认是 1，表示底盘处于停止状态。只有调用 `ChassisSetVelocity()` 才会清 0。

### 3.5.4 `ChassisHandle()`

```cpp
void ChassisHandle()
{
    if (ChassisStopFlag == 0) {
        WheelsSpeedCalc(FBVelocity, LRVelocity, RTVelocity);
    }
    CMFL.Handle();
    CMFR.Handle();
    CMBL.Handle();
    CMBR.Handle();
}
```

- 没急停时，先做麦轮逆运动学解算，给四个电机设目标速度。
- 然后四个电机各自跑 PID。
- 即使急停，`Handle()` 也会调用，但 `Motor::stopFlag = 1` 会把电流强制为 0。

### 3.5.5 `ChassisSetVelocity()`

```cpp
void ChassisSetVelocity(float _fbV, float _lrV, float _rtV)
```

- `_fbV`：前后速度，向前为正。
- `_lrV`：左右速度，向右为正。
- `_rtV`：旋转速度，顺时针为正，单位 RPM。
- 清 `ChassisStopFlag`，保存速度。

### 3.5.6 `ChassisStop()`

```cpp
void ChassisStop()
```

- `ChassisStopFlag = 1`
- 四个电机全部 `Stop()`。

### 3.5.7 `WheelsSpeedCalc()`

```cpp
void WheelsSpeedCalc(float fbVelocity, float lrVelocity, float rtVelocity)
```

这是麦轮逆运动学：

1. 把旋转速度从 RPM 转成 rad/s：

```cpp
rtVelocity = RPM2RADpS(rtVelocity);
```

2. 计算等效旋转半径：

```cpp
const float rotateRadius = (TRACK_WIDTH + WHEEL_BASE) / 2.0f;
```

3. 计算四个轮子的线速度：

```cpp
CMFLSpeed = fb + lr + rt * R;
CMFRSpeed = fb - lr - rt * R;
CMBLSpeed = fb - lr + rt * R;
CMBRSpeed = fb + lr - rt * R;
```

4. 线速度除以轮子半径，得到角速度：

```cpp
CMFLSpeed = CMFLSpeed / (WHEEL_DIAMETER / 2.0f);
```

5. 角速度转 RPM：

```cpp
RADpS2RPM(CMFLSpeed)
```

6. 乘方向修正系数，给电机设目标速度：

```cpp
CMFL.SetTargetSpeed(CMFL_DIR * RADpS2RPM(CMFLSpeed));
```

方向系数：

```cpp
#define CMFL_DIR 1.0f
#define CMFR_DIR 1.0f
#define CMBL_DIR 1.0f
#define CMBR_DIR 1.0f
```

如果某个轮子实际转向和期望相反，只改对应的一行 `1.0f` 为 `-1.0f`，不要改解算公式。

## 3.6 ControlTask.h / ControlTask.cpp

遥控器控制逻辑。

### 3.6.1 `CtrlHandle()`

```cpp
void CtrlHandle()
{
    if (RemoteControl::rcInfo.sRight == DOWN_POS) {
        // 右侧 SC 开关下档：急停
        ChassisStop();
        UserStop();
    } else {
        switch (RemoteControl::rcInfo.sLeft) {
        case UP_POS:
            // 左侧 SB 开关上档：遥控器直接控制底盘
            ChassisSetVelocity(
                RemoteControl::rcInfo.right_col * 4.2,
                RemoteControl::rcInfo.right_rol * 4.2,
                RemoteControl::rcInfo.left_rol * 60
            );
            break;
        case MID_POS:
            // 左二档：学生自己写
            break;
        case DOWN_POS:
            // 左三档：学生自己写
            break;
        }
    }
}
```

含义：

- `sRight == DOWN_POS`：**急停**，底盘和用户机构全部停止。
- `sLeft == UP_POS`：
  - 右摇杆上下 → 前后移动，最大约 `4.2 m/s`。
  - 右摇杆左右 → 左右平移，最大约 `4.2 m/s`。
  - 左摇杆左右 → 旋转，最大 `60 RPM`。
- `sLeft == MID_POS` / `DOWN_POS`：预留，学生自己加功能。

注意：`ControlTask.h` 里声明的 `CtrlHandle(CTRL_CONTROL_T)` 和 `.cpp` 里的 `CtrlHandle()` 签名不一致。实际编译时用的是 `Device.h` 里的 `void CtrlHandle()`，头文件里那个声明没有被定义。以后如果按 `ControlTask.h` 去调用会链接不到。

这些文件大部分是 STM32CubeMX 自动生成的，一般不需要大改。理解它们的作用即可。

| 文件 | 作用 | 关键配置 |

| `Src/main.c` | 系统时钟和错误处理 | `SystemClock_Config()` 配到 168MHz；`Error_Handler()`；**没有 `main()`** |

| `Src/system_stm32f4xx.c` | CMSIS 系统初始化 | FPU、向量表、`SystemCoreClock` |
| `Inc/*.h` | 外设声明 | 各个 `hxxx` 句柄和 `MX_xxx_Init()` 原型 |

重点说几个。

### 4.1 `Src/tim.c`

- **TIM1**：PSC=167，ARR=19999 → 50Hz，CH1~CH4 输出舵机 PWM，引脚 PE9/PE11/PE13/PE14。
- **TIM8**：PSC=167，ARR=19999 → 50Hz，CH1~CH3 输出舵机 PWM，引脚 PC6/PI6/PI7。
- **TIM4**：PSC=0，ARR=20999，CH3 输出蜂鸣器 PWM，引脚 PD14。
- **TIM5**：PSC=0，ARR=65535，CH1~CH3 输出 RGB LED PWM，引脚 PH10/PH11/PH12。
- **TIM10**：PSC=167，ARR=999 → 1kHz，也就是 1ms 中断，整个工程的控制节拍。
- **TIM1 和 TIM10 共用中断向量** `TIM1_UP_TIM10_IRQn`，所以 `stm32f4xx_it.c` 里同时调用 `HAL_TIM_IRQHandler(&htim1)` 和 `HAL_TIM_IRQHandler(&htim10)`。

### 4.2 `Src/can.c`

- CAN1：PD0=RX，PD1=TX。
- CAN2：PB5=RX，PB6=TX。
- 预分频 3，BS1=10TQ，BS2=3TQ，SJW=1TQ。
- APB1 是 42MHz，42MHz / 3 / (1+10+3) = **1Mbps**，这是 RoboMaster 电调的标准波特率。
- CAN1/CAN2 的 RX0 中断优先级都是 0。

### 4.3 `Src/usart.c`

- **USART1**：115200，PB7=RX，PA9=TX，DMA2 Stream2 接收、Stream7 发送，优先级 8。
- **USART3**：100000，PC11=RX，PC10=TX，DMA1 Stream1 接收，优先级 0。这个口接 DBUS 接收机。
- **USART6**：115200，PG9=RX，PG14=TX，优先级 8。

### 4.4 `Src/adc.c`

- ADC1 采集内部 `VREFINT`，用来校准实际 VDDA。
- ADC3 采集 `ADC3_IN8`，引脚 PF10，用来测电池分压。
- 12 位分辨率，连续转换，软件启动。

### 4.5 `Src/gpio.c`

配置了：

- `OLED_BUTTON`：PF1，输入。
- `IST8310_RSTN`：PG6，输出。
- `IST8310_DRDY`：PG3，下降沿中断。
- `KEY`：PA0，上升/下降沿中断。
- `CS1_ACCEL`：PA4，输出。
- `INT1_ACCEL` / `INT1_GRYO`：PC4/PC5，下降沿中断。
- `OLED_RST` / `CS1_GYRO` / `OLED_DC`：PB12/PB0/PB14，输出。

### 4.6 `Src/spi.c`

- **SPI1**：模式 3，约 328kbps，PB3=SCK，PB4=MISO，PA7=MOSI，片选 PA4/PB0，接 BMI088。
- **SPI2**：模式 0，约 164kbps，PB13=SCK，PI2=MISO，PB15=MOSI，接 OLED。

### 4.7 `Src/i2c.c`

- I2C3，400kHz 快速模式，PC9=SDA，PA8=SCL，接 IST8310 磁力计。

### 4.8 `Src/iwdg.c`

- 独立看门狗，LSI 32kHz，预分频 8，重装 4095，超时约 1 秒。
- 但 `main()` 里的 `MX_IWDG_Init()` 被注释掉了，所以当前没有真正启用。

### 4.9 USB 相关

- `usb_device.c`：初始化 USB 设备库，注册 CDC 类。
- `usbd_cdc_if.c`：CDC 虚拟串口，收发缓冲区各 2048 字节。
  - `CDC_Transmit_FS(Buf, Len)` 可以往电脑发数据，调试时很有用。
- `usbd_conf.c`：USB 底层 PCD 驱动，配置端点、FIFO、中断回调。
- `usbd_desc.c`：USB 描述符，包括 VID/PID、厂商、产品名、序列号。

## 七、常见坑与注意事项

### 7.1 `main()` 不在 `Src/main.c`

### 7.2 看门狗实际上没开

`main()` 里：

```cpp
// MX_IWDG_Init();
```

被注释掉了，所以独立看门狗没有启动。

而且 `HAL_TIM_PeriodElapsedCallback()` 里的喂狗条件是：

```cpp
if (vccBat < 10 && hiwdg.Instance != nullptr)
    HAL_IWDG_Refresh(&hiwdg);
```

正常电池电压大约 24V，`vccBat` 不会小于 10，所以即使打开了 IWDG，也几乎不会喂狗，会不断复位。以后要启用看门狗，这个条件需要改。

### 7.3 `ControlTask.h` 的函数声明和实现不一致

头文件里是：

```cpp
CTRL_ERROR_E CtrlHandle(CTRL_CONTROL_T _ctrlControl);
```

实现是：

```cpp
void CtrlHandle();
```

实际用的是 `Device.h` 里的无参版本。头文件里那个带参版本没有定义，不要直接拿去调用。

### 7.4 `UserTask.h` 声明了舵机，但没有定义

```cpp
extern Servo ClawServo, TurnLServo, TurnRServo, ShovelLServo, ShovelRServo;
```

这些只是 `extern` 声明。你要用的话，必须在某个 `.cpp` 里定义它们，例如：

```cpp
SERVO_INIT_T clawInit = {
    .servoType = POSITION_180,
    .servoID = SERVO_ID_1,
    .firstAngle = 0,
    .angleLimit_Min = 0,
    .angleLimit_Max = 180
};
Servo ClawServo(&clawInit);
```

否则链接会报 `undefined reference`。

### 7.5 `Servo::Init()` 是 private，而且没人调用

`Servo::Init()` 在 `Servo.h` 里是私有静态函数，外部调不到。当前舵机实际是靠 `SetTargetAngle()` 里的 `HAL_TIM_PWM_Start()` 启动的。

另外 `firstAngle` 只写入了 CCR，但构造函数没有启动 PWM 通道，所以上电时不会立刻转到 `firstAngle`，第一次 `SetTargetAngle()` 才会输出。

### 7.6 Flash 读写函数有指针/长度问题

`bsp_flash_write()` 里的循环结束条件：

```cpp
ptr < (uint32_t*)(sizeof(flash_data_t)/4 + _flashData)
```

`_flashData` 是 `flash_data_t*`，加 `128` 会跳过 `128 * sizeof(flash_data_t)` 字节，而不是 128 字节。这个函数目前没有被调用，但一旦启用会写坏内存。

`bsp_flash_read()` 里：

```cpp
memcpy(_flashData, (uint32_t*)FLASH_SECTOR_9_ADDRESS,
       sizeof(flash_data_t)/4);
```

只拷贝了 `128` 字节，而结构体是 `512` 字节。应该改成 `sizeof(flash_data_t)`。

### 7.7 PID 的 `ki = 0` 会做 0/0

`PIDCalc()` 里有：

```cpp
INRANGE(PIDInfo.errSum,
        -1 * PIDInfo.componentKiMax / PIDInfo.ki,
        PIDInfo.componentKiMax / PIDInfo.ki);
```

当 `ki = 0` 时，这里会算 `0/0`，得到 `NaN`。虽然当前 `componentKi` 最后乘 `ki` 还是 0，影响不大，但严格来说应该加一个 `if (ki != 0)` 保护。

### 7.8 底盘默认是停住的

`ChassisStopFlag` 初始值是 `1`，所以上电后底盘不会动，直到 `ChassisSetVelocity()` 被调用。

### 7.9 参数需要按实际机器人调

- `WHEEL_DIAMETER`、`TRACK_WIDTH`、`WHEEL_BASE` 要和实际机械尺寸一致。
- `kp`、`ki`、`kd` 需要调。
- 四个轮子的 `CMFL_DIR` 等方向系数，如果某个轮子反了，只改对应的一行。
- `ChassisSetVelocity()` 里的 `4.2`、`4.2`、`60` 也要按实际速度需求调。

### 7.10 `CMakeLists.txt` 里的 `userCode/bsp` 不存在

```cmake
"userCode/bsp/Src/*.*"
...
userCode/bsp/Inc
```

仓库里没有 `bsp` 目录，所以这两处是空的，不影响编译。如果以后加 BSP，可以建这个目录。

### 7.11 串口和接收机

`USART3` 在代码里配置为：

- 波特率 `100000`
- 8 数据位
- 1 停止位
- 无校验

如果遥控器接收机没有数据，先检查：

- 接收机是否对码成功。
- 接收机是否配置为 W.BUS 模式。
- DBUS 线是否插在开发板 DBUS 接口。
- 波特率/校验位是否和接收机一致。

## 总结

这个工程的骨架可以概括成：

```text
CubeMX 初始化外设
        ↓
Device.cpp 的 main() 启动 1ms 定时器
        ↓
TIM10 每 1ms 触发一次
        ↓
CtrlHandle 读遥控器
        ↓
ChassisHandle 解算底盘
        ↓
UserHandle 控制机构
        ↓
Motor::CANPackageSend 把电流发给电调
        ↓
CAN 接收中断收回电调反馈，形成闭环
```

你真正要改的代码，90% 都在：

```text
userCode/tasks/Src/ControlTask.cpp
userCode/tasks/Src/ChassisTask.cpp
userCode/tasks/Src/UserTask.cpp
```

底层外设和驱动一般不用动。先把 `Device.cpp` 的 `main()` 和 1ms 回调看懂，再看 `ControlTask → ChassisTask → Motor` 这条链，整个工程就通了。
